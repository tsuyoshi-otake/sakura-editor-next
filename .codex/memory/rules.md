# Verified project rules

- An MSBuild target that deletes or regenerates a linker output must have an `Inputs`/`Outputs` contract covering the real link inputs and imported project files. An unconditional pre-link delete makes every nominal no-op build relink.
- Keep source/assembly listings opt-in for the local edit loop; enable `/FAsu` only for diagnostics or distribution workflows that consume the `.asm` artifacts.
- If a CMake-generated Visual Studio child build loses its Tracker parent while `cl.exe` or `link.exe` remains suspended, scope `TrackFileAccess=false`, node-reuse disabling, and `/nr:false` to those generated children. Keep FileTracker enabled on the top-level project so normal incremental compilation remains correct.
- For incremental-build benchmarks in a shared worktree, inspect each sample for compiler, linker, delete-helper, and nested-build commands. Reject or explicitly label any sample whose source timestamp changed concurrently; a fast wall time alone does not prove a true no-op.
- When a Release build uses `/GL`, a successful `ClCompile` containing `/FAsu` is not sufficient evidence that its `.asm` exists. For a bounded single-file check, use an equivalent non-`/GL` configuration; otherwise validate after the complete link-time code-generation phase.
- Do not give concurrently runnable developer builds one fixed MSBuild file-log path. Stream to stdout or generate a unique log name so one build cannot lock or truncate another build's diagnostics.
- For large-document startup benchmarks, a ready caption and the first `WaitForInputIdle` can precede completed layout. Require the editor's vertical range to cover every physical input line, then copy the visible window rectangle immediately. Keep the first `DwmFlush` as an initial-frame proxy only; a final flush, second `WaitForInputIdle`, or `PrintWindow` on an inactive/large window can block for tens of seconds and must not gate regressions.
- In PowerShell test harnesses, never use `$host` as a task variable because it aliases the read-only automatic `$Host`. Format numeric method calls before interpolating them into Markdown, and write machine-readable JSON with an explicit BOM-free `UTF8Encoding` when downstream parsers require byte-zero `{`.
- When repository test children reappear after cleanup, inspect the ancestor chain before repeating child-only termination. Stop the scoped runner parent first, then its test/death-test/editor children, and re-list to prove they cannot respawn.
- With single-config CMake generators and MSVC, `CMAKE_SYSTEM_PROCESSOR` can be empty even after a valid x64 compiler probe. Prefer `CMAKE_CXX_COMPILER_ARCHITECTURE_ID`/`MSVC_CXX_ARCHITECTURE_ID` as the fallback; pointer width alone cannot distinguish x64 from ARM64.
- When a generated Windows manifest is resource-compiled as ID 1 for an MSVC CMake target, pass `/MANIFEST:NO` to disable CMake's default linker/`mt.exe` manifest. Otherwise the final link fails on duplicate MANIFEST resources. Resource scripts that embed vcpkg payloads by file name also need the package directory in the target include path for Ninja.
- On this Windows workspace host, use `C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe` for long native test rebuilds. The `amd64` MSBuild launcher left its `cl.exe` child suspended in this session, while the standard launcher rebuilt and linked the same Debug test target successfully.
- In reconnect or resnapshot transport test doubles, keep `Close` state on each channel instance. Sharing closure state across a scripted sequence pre-cancels later connections and produces false retry or readiness failures.
- If a callback may destroy the production owner and therefore its injected fake, assertions after that callback must observe separately owned state. A raw pointer returned before ownership transfer becomes invalid as soon as callback-origin teardown can release the fake, even when the production implementation correctly retains only its own internal lifetime.
- For VS Code Workbench color projection, keep Part roles semantic and distinct: Explorer/Side Bar uses sideBar.background, the Panel uses panel.background, and the Panel-hosted Terminal viewport uses optional terminal.background with panel.background fallback. High Contrast foreground policy must not bypass the terminal viewport role.
- [component graph verification] Do not treat two backends generated by the same manifest generator as independent evidence. Compare the declared semantic graph, each generated backend graph, and observed compiler/linker/task/restore/staging behavior; use normal minimal-closure links as the primary proof and leaf-only whole-archive as an orphan-object audit. - Evidence: Issue #15 third-party findings B-03/B-04 were confirmed against the monolithic CMake/tests1 and role bootstrap paths, then encoded and read back as distinct graduation gates.
- [build entrypoints] Keep batch files, if temporarily retained, as argument/exit-code forwarding shims only. Dependency closure, tool discovery, restore, generation, staging, parallelism, cancellation, and cleanup must belong to one testable build driver with a machine-readable plan. - Evidence: current `build-dev.bat`/`build-sln.bat` contain orchestration and environment logic; Issue #15 v2 removes batch commands from the canonical interface and its read-back contains no old batch entrypoint.
- A nested Workbench View collapse is visibility state, not child/model lifetime. Lay out the
  retained hidden child at its final bounds before showing it, commit one host/child redraw,
  and only then request refresh keyed by document identity/version. Deduplicate an identical
  in-flight version and reject superseded generations; height-only collapse/reopen must not
  walk the model. Evidence: x64 Debug solution build and the 21 focused OUTLINE lifecycle,
  geometry, border, owner-order, 20-cycle cache, dedupe, and stale-generation tests pass.
- A generated MSBuild project shared by multiple semantic contexts must condition each
  `ProjectReference` on every physical `Configuration|Platform` where its link edge is active,
  and reject case-insensitive physical-key collisions. Evidence: Issue #15 Debug/Release fixture
  evaluates to `provider.vcxproj` in Debug and no reference in Release via MSBuild `-getItem`.
- A component-local generated-output check must not regenerate the repository-wide projection or
  walk the entire generated tree. Validate the current graph metadata and selected native-closure
  files against content hashes in the committed stamp; leave unexpected-file detection to the full
  generation check. Evidence: Issue #15 unit fixtures detect Debug-only provider corruption only in
  Debug/full checks and fail if the local path invokes the full renderer.
- Static-library link evidence requires an expected selected archive member in the MAP, not merely
  the provider library name elsewhere in the file. Evidence: Issue #15 provider-name-only negative
  test fails, while URI MSBuild and CMake maps select their expected `UriIdentity` members.
- [resource inventory] Detect a resource file's BOM before lexical include scanning, and separate vendored
  RC/RC2 inputs from Sakura-owned component inputs before assigning missing-owner or generated-output findings.
  Evidence: the Issue #15 inventory recovered 19 include edges and 6 generated includes from UTF-16 Sakura/language
  resources while keeping 7 external resource files outside Sakura ownership blockers.
- [native resource evidence] Validate the current product hash before PE resource enumeration, open the image with
  data/image-resource flags, and keep top-level type/name/language/content observation separate from nested numeric
  resource-ID compatibility. A golden ID contract must include the canonical header mapping, each language's RC/RC2
  references, and nested IDs decoded from every language image; hash every input so later mutation makes evidence stale.
  Evidence: Issue #15 observed 260 stable top-level entries without executing `sakura.exe`, then matched the versioned
  three-language baseline and removed only `RESOURCE_ID_COMPATIBILITY_UNOBSERVED` while other strict gates stayed red.
- [shared generator clean ownership] A generator workspace consumed by multiple leaf projects is not owned by any
  leaf's `CoreClean`. Preserve it by default and let only an explicit full-observation or repository-wide clean owner
  delete it; resource-only leaves must not ProjectReference the final product merely to reach generated contracts.
  Evidence: Issue #15 x64 Debug/Release language Rebuilds completed in 2.08/2.03 seconds with zero warnings, kept five
  shared CMakeTools hashes and mtimes unchanged, and left the pre-existing product native evidence valid without a rebuild.
- [content-stable Visual Studio CMake generators] A CMake custom target in a generated Visual Studio project may run
  every time because CMake emits a missing phony output. Make the target a bounded content-aware observer: compare exact
  input/output hashes, resolve symlink providers, hold one lock across shared materialization, and publish state only after
  all outputs succeed. Do not use unconditional `touch`. Evidence: Issue #15 reduced 10 undeclared generator-input gaps
  to zero; consecutive Debug/Release generation builds kept 12 output sizes and mtimes unchanged, while cached ctags ran
  successfully even with deliberately invalid archive and compiler commands.
- VS-bundled CMake 3.31.6 can fast-fail with `0xC0000409` when either its source or build tree uses a
  Japanese path. Keep the checkout authoritative, but run only the affected CMake component child
  through a short-lived ASCII junction verified with `os.path.samefile`; persist the lexical alias so
  observed Ninja evidence can recreate the same file identity, and clean the run-owned junction on
  success, failure, and timeout. Preserve object-path headroom for the longer physical checkout spelling:
  `CMAKE_OBJECT_PATH_MAX=220` passed normal/space/Japanese URI builds here, while 180 was below the
  ASCII-space object-directory prefix and broke Ninja directory creation.
- [split test inventory] Preserve stable test IDs independently of runner/selector. Refresh from every declared runner, reject any disappeared selector unless it has an explicit reviewed remap, and treat newly discovered selectors as guarantee additions; then require exact missing/unexpected zero against the same configuration that owns the baseline. - Evidence: the Issue #15 URI split kept 9 stable IDs while moving runners, exposed a stale baseline with 2 renames and 83 additions, and converged to an exact Debug inventory of 2,799 selectors with no silent loss.
- [cmake msvc showincludes] Do not rely on CMake's locale-sensitive MSVC `/showIncludes` auto-probe when the compiler emits UTF-8 diagnostics. Pin or validate the observed prefix in the generated child project, rebuild the dependency database after changing it, and require non-empty `ninja -t deps` before treating include-closure evidence as valid. - Evidence: the Issue #15 filesystem CMake boundary initially reported zero observed headers because `rules.ninja` contained a mojibake prefix; after the prefix was fixed and objects were rebuilt, Debug/Release boundary checks passed with no input-observation failures.
- [filesystem leaf] A filesystem provider split is not green merely because a static archive links. Require a contracts-only public include view, a factory-composed default provider, package/resource-less standalone tests for bounds and terminal watch cleanup, and a declared filesystem-to-URI link closure. - Evidence: `sakura_filesystem_tests` passed all 13 selectors in MSVC and CMake/Ninja Debug/Release, with boundary failures empty and package restore suppressed.
- [storage model leaf] Split the immutable storage type contract before moving stateful storage services. A public `StorageTypes` archive and contract runner may be green only when the stateful in-memory/atomic services, Control RPC, persistence, and lifecycle ownership remain explicitly marked legacy and gated separately. Preserve stable test IDs with a reviewed runner remap; never infer storage-service independence from a model-only archive. - Evidence: `sakura_storage_tests` passed 2 selectors in MSVC and CMake/Ninja Debug/Release with closure `sakura_storage_tests -> sakura_storage`, while `CInMemoryStorageService` and `CAtomicFileStorageService` remained outside the slice.
- [storage public contract] Promote `IStorageService` and `IStorageChangeSubscription` to the same public include view as `StorageTypes` before moving stateful implementations. Delete the private interface header and switch every consumer explicitly; compile-only virtual-destructor checks are useful, but do not count them as service lifecycle or fake-replacement evidence. - Evidence: old `platform/storage/IStorageService.h` references/files are zero, while Debug/Release MSVC/CMake storage boundaries and full solution links remained green; the stateful `.cpp` files remain legacy by design.
- [native system-library ownership] A static library cannot carry its native API link requirements by itself. Declare each system library on the owning component in the semantic manifest, validate its name, and project the deterministic final-link union into both MSBuild and CMake. Do not reintroduce `#pragma comment(lib)` in product or test sources. - Evidence: `sakura_security` initially failed with unresolved Advapi32 symbols; adding manifest `system_libraries=["advapi32"]` made MSVC/CMake Debug/Release component links and full solutions pass.
- [new split-runner IDs] Stable test IDs must remain independent from runtime mappings, but a newly discovered selector from a newly split runner must use that runner's namespace. Preserve existing remapped IDs; otherwise a new leaf test is silently attributed to `tests1` and future runner-set verification loses ownership. - Evidence: the security refresh added `sakura_security_tests:CurrentUserSecurityAttributes.InitializesProtectedCurrentUserAttributes` while retaining all prior 2,799 IDs.
- [MSBuild context projection] A generated ProjectReference outside the solution may default to Win32 when its child project is evaluated through a legacy consumer. Emit `SetConfiguration` and `SetPlatform` metadata for every active physical context, and register the generated leaf in handwritten solution configurations until solution generation owns the projection. - Evidence: the security solution first selected Debug|Win32; explicit metadata plus the solution project/config entries yielded Debug/Release x64 links.
- [stateful authority port] Before moving a stateful storage implementation, expose a narrow public lifecycle port (`Open`/`Close`/`IsOpen`) and inject it through the Control composition factory. Keep writer locks, file format, OS I/O seams, queues, and mutable state behind the selected implementation; do not expose them through a runtime header or a service locator. The Control owner must close the authority before releasing its last reference, while Editor may depend only on the IPC client/cache direction. - Evidence: `IStorageAuthority` and `storageFactory` removed concrete storage/I/O types from `ControlPlatformRuntime.h`; fake lifecycle contract and existing Control runtime tests passed in MSVC/CMake Debug/Release, with process audit `[]`.
- [authority composition boundary] Control RPC adapters and the service host must accept `IStorageAuthority` rather than the generic storage service, while the synchronous protocol session may consume only the base `IStorageService` contract. The runtime owns `Open`/`Close`; an active-frame drain test must prove `BeginStopping` waits before returning. - Evidence: the authority-narrowed adapters/host built in MSVC Debug/Release, focused filters passed 63/63 and 54/54, and process audit returned `[]`.
- [durable authority ownership] Move a stateful durable provider only after a public lifecycle/factory contract exists. Keep file format, writer lock, and Win32 I/O private; move the source/private header into the provider archive, declare its security/system dependencies, remove the concrete include from the Control runtime, and verify that the public factory persists and reopens data. - Evidence: `CAtomicFileStorageService` and `StorageAuthorityFactory` are owned by `sakura_storage`, `ControlPlatformRuntime.cpp` uses the public factory, and `sakura_storage_tests` passes the real persistence/reopen selector in all four MSVC/CMake Debug/Release contexts.
- [static private-link closure] `propagation=none` must not erase a private static archive needed at a native final-link root. MSBuild `ProjectReference` and CMake `PRIVATE` propagation differ, so the generator must project `graph.final_link_closure` explicitly and boundary MAP/link evidence must prove provider libraries and selected members. - Evidence: the storage boundary initially failed with a missing `sakura_security.lib`; after final-link projection and `bcrypt` declaration, all four storage boundary checks passed with closure `sakura_security`/`sakura_storage`/`sakura_storage_tests`.
- [named-pipe lifecycle evidence] Treat transport bounds and shutdown as separate evidence: test frame/session limits, pending-accept cancellation, callback-stop behavior, and external worker join. Existing transport tests count only when the full filter passes and process cleanup is rechecked. - Evidence: `ControlIpcNamedPipeTransport` passed 9/9 after the durable-provider move and process audit returned `[]`.
- [request leaf evidence] A request/provider split must expose transport-neutral public contracts and keep WinHTTP behind typed adapters. The standalone runner must cover cancellation, redirect, cache, bounded retry, and sensitive-header policy without UI/resources; the existing tests1 RequestService cases remain integration compatibility evidence. Declare `winhttp` in the manifest and project it into final links—static provider archives do not have a MAP, so boundary evidence belongs to the executable contract runner. - Evidence: `sakura_request_tests` passed 5/5 in MSVC and CMake/Ninja Debug/Release, boundary closures were clean, and the focused tests1 filter passed 22/22.
