# Verified project rules

- An MSBuild target that deletes or regenerates a linker output must have an `Inputs`/`Outputs` contract covering the real link inputs and imported project files. An unconditional pre-link delete makes every nominal no-op build relink.
- Keep source/assembly listings opt-in for the local edit loop; enable `/FAsu` only for diagnostics or distribution workflows that consume the `.asm` artifacts.
- If a CMake-generated Visual Studio child build loses its Tracker parent while `cl.exe` or `link.exe` remains suspended, scope `TrackFileAccess=false`, node-reuse disabling, and `/nr:false` to those generated children. Keep FileTracker enabled on the top-level project so normal incremental compilation remains correct.
- For incremental-build benchmarks in a shared worktree, inspect each sample for compiler, linker, delete-helper, and nested-build commands. Reject or explicitly label any sample whose source timestamp changed concurrently; a fast wall time alone does not prove a true no-op.
- When a Release build uses `/GL`, a successful `ClCompile` containing `/FAsu` is not sufficient evidence that its `.asm` exists. For a bounded single-file check, use an equivalent non-`/GL` configuration; otherwise validate after the complete link-time code-generation phase.
- Do not give concurrently runnable developer builds one fixed MSBuild file-log path. Stream to stdout or generate a unique log name so one build cannot lock or truncate another build's diagnostics.
- For large-document startup benchmarks, a ready caption and the first `WaitForInputIdle` can precede completed layout. Require the editor's vertical range to cover every physical input line, then copy the visible window rectangle immediately. Keep the first `DwmFlush` as an initial-frame proxy only; a final flush, second `WaitForInputIdle`, or `PrintWindow` on an inactive/large window can block for tens of seconds and must not gate regressions.
- In PowerShell test harnesses, never use `$host` as a task variable because it aliases the read-only automatic `$Host`. Format numeric method calls before interpolating them into Markdown, and write machine-readable JSON with an explicit BOM-free `UTF8Encoding` when downstream parsers require byte-zero `{`.
- When repository test children reappear after cleanup, inspect the ancestor chain before repeating child-only termination. Stop the scoped runner parent first, then its test/death-test/editor children, and re-list to prove they cannot respawn.
- With single-config CMake generators and MSVC, `CMAKE_SYSTEM_PROCESSOR` can be empty even after a valid x64 compiler probe. Prefer `CMAKE_CXX_COMPILER_ARCHITECTURE_ID`/`MSVC_CXX_ARCHITECTURE_ID` as the fallback; pointer width alone cannot distinguish x64 from ARM64.
- When a generated Windows manifest is resource-compiled as ID 1 for an MSVC CMake target, pass `/MANIFEST:NO` to disable CMake's default linker/`mt.exe` manifest. Otherwise the final link fails on duplicate MANIFEST resources. Resource scripts that embed vcpkg payloads by file name also need the package directory in the target include path for Ninja.
- On this Windows workspace host, use `C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe` for long native test rebuilds. The `amd64` MSBuild launcher left its `cl.exe` child suspended in this session, while the standard launcher rebuilt and linked the same Debug test target successfully.
- In reconnect or resnapshot transport test doubles, keep `Close` state on each channel instance. Sharing closure state across a scripted sequence pre-cancels later connections and produces false retry or readiness failures.
- If a callback may destroy the production owner and therefore its injected fake, assertions after that callback must observe separately owned state. A raw pointer returned before ownership transfer becomes invalid as soon as callback-origin teardown can release the fake, even when the production implementation correctly retains only its own internal lifetime.
- For VS Code Workbench color projection, keep Part roles semantic and distinct: Explorer/Side Bar uses sideBar.background, the Panel uses panel.background, and the Panel-hosted Terminal viewport uses optional terminal.background with panel.background fallback. High Contrast foreground policy must not bypass the terminal viewport role.
- [component graph verification] Do not treat two backends generated by the same manifest generator as independent evidence. Compare the declared semantic graph, each generated backend graph, and observed compiler/linker/task/restore/staging behavior; use normal minimal-closure links as the primary proof and leaf-only whole-archive as an orphan-object audit. - Evidence: Issue #15 third-party findings B-03/B-04 were confirmed against the monolithic CMake/tests1 and role bootstrap paths, then encoded and read back as distinct graduation gates.
- [build entrypoints] Keep batch files, if temporarily retained, as argument/exit-code forwarding shims only. Dependency closure, tool discovery, restore, generation, staging, parallelism, cancellation, and cleanup must belong to one testable build driver with a machine-readable plan. - Evidence: current `build-dev.bat`/`build-sln.bat` contain orchestration and environment logic; Issue #15 v2 removes batch commands from the canonical interface and its read-back contains no old batch entrypoint.
- A nested Workbench View collapse is visibility state, not child/model lifetime. Lay out the
  retained hidden child at its final bounds before showing it, commit one host/child redraw,
  and only then request refresh keyed by document identity/version. Deduplicate an identical
  in-flight version and reject superseded generations; height-only collapse/reopen must not
  walk the model. Evidence: x64 Debug solution build and the 21 focused OUTLINE lifecycle,
  geometry, border, owner-order, 20-cycle cache, dedupe, and stale-generation tests pass.
- A generated MSBuild project shared by multiple semantic contexts must condition each
  `ProjectReference` on every physical `Configuration|Platform` where its link edge is active,
  and reject case-insensitive physical-key collisions. Evidence: Issue #15 Debug/Release fixture
  evaluates to `provider.vcxproj` in Debug and no reference in Release via MSBuild `-getItem`.
- A component-local generated-output check must not regenerate the repository-wide projection or
  walk the entire generated tree. Validate the current graph metadata and selected native-closure
  files against content hashes in the committed stamp; leave unexpected-file detection to the full
  generation check. Evidence: Issue #15 unit fixtures detect Debug-only provider corruption only in
  Debug/full checks and fail if the local path invokes the full renderer.
- Static-library link evidence requires an expected selected archive member in the MAP, not merely
  the provider library name elsewhere in the file. Evidence: Issue #15 provider-name-only negative
  test fails, while URI MSBuild and CMake maps select their expected `UriIdentity` members.
- [resource inventory] Detect a resource file's BOM before lexical include scanning, and separate vendored
  RC/RC2 inputs from Sakura-owned component inputs before assigning missing-owner or generated-output findings.
  Evidence: the Issue #15 inventory recovered 19 include edges and 6 generated includes from UTF-16 Sakura/language
  resources while keeping 7 external resource files outside Sakura ownership blockers.
- VS-bundled CMake 3.31.6 can fast-fail with `0xC0000409` when either its source or build tree uses a
  Japanese path. Keep the checkout authoritative, but run only the affected CMake component child
  through a short-lived ASCII junction verified with `os.path.samefile`; persist the lexical alias so
  observed Ninja evidence can recreate the same file identity, and clean the run-owned junction on
  success, failure, and timeout. Preserve object-path headroom for the longer physical checkout spelling:
  `CMAKE_OBJECT_PATH_MAX=220` passed normal/space/Japanese URI builds here, while 180 was below the
  ASCII-space object-directory prefix and broke Ninja directory creation.
