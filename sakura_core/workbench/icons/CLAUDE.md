# Workbench icon guidance

This directory owns the two bundled icon fonts used by native Sakura Editor NEXT
workbench surfaces, and the association data each one is addressed through:

| Font | Purpose | Association data | Provenance |
| --- | --- | --- | --- |
| `codicon.ttf` | Every workbench UI glyph, and the Explorer's file-icon fallback | `CodiconGlyphs.h`, `ExplorerFileIcon.h` | `CODICONS-ATTRIBUTION.md` |
| `seti.ttf` | The Explorer's file icons, as VS Code's default `vs-seti` theme | `SetiIconThemeTable.h` (generated) | `SETI-ATTRIBUTION.md` |

Both are embedded as named `RCDATA` resources in `sakura_rc.rc2` and registered
process-privately through `RegisterEmbeddedFontResource` (`AddFontMemResourceEx`).
Neither is installed into the system font collection or written to disk, and each
singleton (`CCodiconFont`, `CSetiFont`) reports `IsAvailable()` so a caller can
fail over rather than draw a code point in a substituted face.

- Keep icon lookup restricted to the bundled, versioned vocabularies. A glyph
  this repository cannot name is a missing table entry, not a reason to load an
  external font file or package metadata.
- `SetiIconThemeTable.h` is generated by `tools/generate-seti-icon-theme.py` from
  Microsoft's own theme document. **Do not edit it by hand.** Regenerate it, and
  update `SETI-ATTRIBUTION.md` in the same change when the upstream pin moves.
- Unknown identifiers must fall back safely: an unmatched file name resolves to
  the theme's own `file` icon, and an unavailable Seti registration falls back to
  the Codicon associations.
- Keep glyph lookup allocation-free on paint paths where practical. Both
  resolvers are `constexpr` over sorted tables, so a lookup costs a binary search
  and no allocation.
- Preserve the existing C++ encoding rules when editing sources in this tree.
- The bundled artwork is third-party code under its own license. Each attribution
  file states what ships, where it came from, and what was changed; a change that
  adds, removes, or modifies a bundled font must update that file and the
  `license\` payload lists in `build-installer.bat`, `zipArtifacts.bat`,
  `installer/sakura-common.iss`, and `installer/readme.md` together.

VS Code extension compatibility and externally supplied icon themes were
retired for supply-chain safety. See
[`../../../docs/vscode-extension-compatibility-retirement.md`](../../../docs/vscode-extension-compatibility-retirement.md).
Bundling `vs-seti` is not a reversal of that decision: the theme is converted to
first-party data at build time by a pinned, verifying generator, and nothing is
parsed or loaded from a package at runtime.
